# Agent audit bundle spec

What gets packaged for ChatGPT Agent review after an
installed-device or Maestro audit run, and how the bundle
crosses the laptop ↔ Agent boundary while honouring rule 22's
privacy floor.

This is **doc only**. No app code. No EAS build.

## 0. The problem

Audit captures (PNGs + manifest) live in `artifacts/app-audit/<method>/<timestamp>/`
on the laptop. ChatGPT Agent runs in a separate context that
can't read the laptop filesystem directly. Aaron is the
courier — he uploads the bundle into Agent.

This spec defines the bundle's **format**, **redaction
contract**, and **import contract** for Agent so that:

1. Agent receives a self-contained, redacted, machine-
   readable summary plus the visual evidence it needs.
2. Aaron's manual step is one-tap upload, not file-by-file
   selection.
3. The bundle never leaks PII / tokens / secrets per rule 22.
4. Agent's review feeds back into the action ledger per
   rule 18.

## 1. Bundle format

A single `.zip` archive with a deterministic structure:

```
audit-bundle-<gateType>-<isoTimestamp>.zip
├── manifest.json                      # see § 2
├── repo-snapshot.json                 # see § 3
├── screens/
│   ├── 01-home.png
│   ├── 02-train.png
│   └── ...                            # PNG files matching manifest.screens[]
├── recordings/                        # optional; only present if screen-record gates ran
│   └── 04-health-connect-connect.mov
├── action-ledger-snapshot.json        # see § 4
└── README.md                          # see § 5
```

Generated by an `npm run audit:bundle` helper (Codex follow-up,
see § 7).

## 2. manifest.json — extended

Reuses the schema from `audit-screenshots.mjs` + adds
bundle-specific fields:

```json
{
  "schemaVersion": 1,
  "bundleType": "agent_audit_bundle",
  "captureMethod": "iphone_mirroring | iphone_screen_record | simulator_script | maestro_v3 | mixed",
  "gateType": "release_gate | fs_xxx_functional | forever_improve_drift | health_connect_crash_retest | ios_testflight_install | pre_eas_sanity | admin_dev_proof_checklist",
  "fsCandidate": "FS-020 | null",
  "iosBuildNumber": "19",
  "androidVersionCode": 20,
  "appVersion": "0.1.0",
  "device": "iPhone 15 Pro",
  "iosVersion": "18.2",
  "platform": "ios",
  "capturedAt": "2026-05-09T02:30:00Z",
  "repoBranch": "main",
  "repoShortHead": "<sha>",
  "screens": [
    { "filename": "01-home.png", "screen": "home", "captureTimestamp": "..." }
  ],
  "recordings": [
    { "filename": "04-health-connect-connect.mov", "screen": "health-connect-connect", "durationSeconds": 12 }
  ],
  "containsRealUserData": true,
  "redactionApplied": true,
  "redactionLog": ["blurred name in 03-manage-sources.png header"],
  "skippedScreens": [
    { "screen": "ios-settings-deep-link", "reason": "leaves app process; out of scope for this bundle" }
  ],
  "auditNotes": "Health Connect → Connect tap completed without crash on v20."
}
```

Field discipline:

- `containsRealUserData: true` triggers a redaction-required
  flag downstream.
- `redactionApplied` MUST be `true` when sharing externally.
  Default is `false` for local-only bundles.
- `redactionLog[]` lists what was redacted (per-screen).
  The bundle never says "redacted" without saying what.

## 3. repo-snapshot.json

Deterministic snapshot of repo state at capture time:

```json
{
  "branch": "main",
  "shortHead": "<sha>",
  "headCommit": {
    "subject": "<commit subject line>",
    "author": "Aaron Maher",
    "committedAt": "<iso>"
  },
  "dirtyFileCount": 0,
  "dirtyFiles": [],
  "stagedFileCount": 0,
  "operatingRulesCount": 23,
  "topPriorities": [
    { "rank": 1, "title": "..." },
    ...
  ]
}
```

Pulled from `git log -1 --format="%s|%an|%aI"` + `git status --short`
+ the canonical `topPriorities` array we now write into
`connector_work_status` per rule 18.

This is the "what was the codebase like when this audit
ran" reference Agent uses to ground its review.

## 4. action-ledger-snapshot.json

Subset of the live `connector_handoff` payload at capture
time:

```json
{
  "schemaVersion": 1,
  "snapshotAt": "<iso>",
  "agent_qa_result": {
    "status": "partial",
    "gate": "release_gate",
    "platform": "android",
    ...
  },
  "auditFindings": [...],     // last N findings from connector_handoff
  "topPriorities": [...],     // pulled from connector_work_status
  "rule18Reinforced": "Terminal state is evidence, not memory..."
}
```

This gives Agent the canonical operator state in machine-
readable form without needing to re-call MCP itself (per
`docs/AGENT_MCP_ACCESS.md` § 5 fallback workflow).

## 5. README.md (inside the bundle)

Self-explanatory cover note Agent reads first:

```markdown
# Agent audit bundle — <gateType>

Captured: <isoTimestamp>
Method: <captureMethod>
Build: iOS <buildNumber> / Android v<versionCode>

## Mission for Agent

1. Read manifest.json + repo-snapshot.json + action-ledger-snapshot.json.
2. Review screens/ in numeric order. For each, judge against
   the rubric in docs/INSTALLED_DEVICE_AUDIT_PLAYBOOK.md § 5
   (render correctness / copy truthfulness / cross-platform
   purity / auth gating / MCP freshness / no PII leak).
3. If recordings/ is present, review for the specific
   behavior described in the screen's notes.
4. Produce: AGENT_QA_RESULT_JSON per the format in
   INSTALLED_DEVICE_QA_RELEASE_GATE.md § AGENT_QA template.
5. Flag any failing rows + propose FS-XXX candidates per
   rule 1 (audit → bundles).

## Rules for Agent's review

- Hypothesis language only when discussing health/skill claims
  (rule 9). No "you should X" / "definitely Y".
- Cross-platform string check: iOS-only words on iOS,
  Android-only on Android.
- No assumption that the build under audit is the latest —
  use repo-snapshot.json's `shortHead` to ground.
- Do NOT request the laptop run additional commands; if
  evidence is missing, say so + propose what to capture
  next, don't fabricate.
- Per rule 11 (MCP-first), prefer the bundled
  action-ledger-snapshot.json over re-calling MCP if the
  Agent runtime can't reach MCP.

## Privacy

This bundle MAY contain real user data (manifest.containsRealUserData).
If `redactionApplied: false`, do NOT quote PII (names,
addresses, dates of birth, health values) in your output.
If `redactionApplied: true`, the redactionLog lists what was
removed.
```

## 6. Redaction contract

Before any bundle leaves the laptop:

1. **Auto-redaction pass** (when implemented per § 7
   helper):
   - Header bars on Manage Sources / Settings / Admin/Dev
     scanned for user name patterns; auto-blur if matched
     against the sign-in user's email/displayName.
   - Health-data values (HRV / RHR / sleep) are kept; the
     point of the audit may be that those values render
     correctly. NOT redacted by default.
   - Journal entry content (Feedback tab Track-Something
     surfaces) is auto-redacted to `<journal text>`
     placeholder; the audit cares about the UI, not the
     content.
   - Admin/Dev → Approval centre shows ledger row text;
     auto-redact `whatNeedsApproval` / `whyItMatters` to
     `<gate body>` placeholders unless `--keep-gate-bodies`
     flag explicitly set.
   - Tokens / secrets visually present (rare; debug
     surfaces only): hard-block bundle generation. Operator
     re-captures with token redacted in-app.
2. **Manual redaction option**: operator can pass `--manual-redact`
   to step through each screen + accept / blur / drop.
3. **`redactionLog[]` mandatory**: the manifest records
   exactly what was redacted, per screen.
4. **No bundle ships with `containsRealUserData: true` AND
   `redactionApplied: false`** to any external surface.

Approval-gated.

## 8. Anti-rules

- **No bundle ships with redactionApplied: false to external.**
  Local-only bundles may keep raw data; anything that
  crosses the laptop boundary is redacted.
- **Token detection hard-blocks.** The pipeline halts
  rather than ship a bundle with possible secret leakage.
- **No screenshots of the unlocked phone keychain or the
  raw EAS console.** Out of bundle scope. Operator captures
  in-app surfaces only.
- **No bundle larger than 100 MB.** Recordings count toward
  the cap; if exceeded, drop recordings or re-encode.
- **No bundle generated from a live build the operator
  isn't running.** Single-build bundles only.
- **No automatic upload.** Aaron is the courier — bundle
  stays on disk until he chooses to upload it.
