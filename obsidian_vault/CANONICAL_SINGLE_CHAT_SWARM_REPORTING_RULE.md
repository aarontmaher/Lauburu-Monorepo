## 2. Invariant Rules for Swarm Delegation & Reporting

### Rule A: Sandbox Isolation (Zero Context Clutter)
1. Heavy intermediate exploration, scratch scripts, hundred-line compiler errors, and exploratory file reads MUST remain quarantined inside the subagents' isolated working directories (`.agents/orchestrator_r*/`, `.agents/worker_*/`, or `sandbox_evolution/`).
2. Subagents are strictly forbidden from dumping raw unparsed logs into the Mother Ship context.

### Rule B: High-Priority Reactive Upstream Reporting
1. All subagents, sentinels, and background monitors MUST emit structured, executive milestone checkpoints directly to the Mother Ship conversation ID using `priority=MESSAGE_PRIORITY_HIGH`.
2. Every upstream report must include:
   - **Phase & Milestone:** (e.g. `Phase 2: Implementation`, `Milestone M5 Complete`).
   - **Files Created/Modified:** Exact clickable file links with byte counts.
   - **Empirical Tri-Proof:** Exact unit test counts and exit codes (`Exit Code 0`, `39/39 passed`).
   - **Current State:** Blockers or next immediate action.

### Rule C: Continuous LoRA Memory & Vault Distillation (/learn & Rule 2)
1. Whenever a background swarm completes a milestone, the verified consensus, architectural decisions, and code diffs must be automatically crystallized into:
   - `obsidian_vault/APPS_AND_FEATURES/`
   - `lora_datasets/continuous_lora_dataset.jsonl`
   - `lora_datasets/architectural_decisions.jsonl`
2. This ensures that even if individual subagents finish and terminate, their learned weights and reasoning traces permanently empower the local `Qwen 3.8 Max` model on Port 8082 at $0 recurring cost.
